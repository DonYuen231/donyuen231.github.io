## Overview

Historic Photo Explorer describes historical photographs for blind and visually impaired readers. You enter a subject and a place. The server finds matching photos in the Library of Congress archive, sends them to Claude, and returns a page with a written description, an estimated time period and notable details for each photo.

It started as my final project for a CS class at CUNY: a mashup of two APIs using only Node.js core modules, with the requests running one after another. I kept that constraint, so there's nothing to install: only `http`, `https` and `fs`, and callback-style asynchronous code.

## How it works

1. **Search.** The browser sends a subject and location to the Node server. The server queries the public Library of Congress JSON API and keeps the first 5 results that have an image.
2. **Download.** The server downloads each image, one at a time, and reads its width and height from the header bytes. If the longest side is under 400 pixels, the photo is marked low resolution.
3. **Describe.** All 5 images go to the Claude API in one request, each labeled with its catalog title and date. The API key stays on the server and never reaches the browser.
4. **Render.** The request uses structured outputs, so the answer always has the same JSON shape. The server builds the HTML itself and escapes every value, instead of trusting model-written markup.

Every outbound request goes through one small HTTPS helper that handles redirects, timeouts and errors. Finished results are cached in memory for an hour.

## Results

Unit tests check the code, but they can't tell whether a description is any good. So I picked 20 Library of Congress photos, each with a cataloger's written summary that the app never sees, and scored every description from 1 to 5 for accuracy, completeness, usefulness to a blind reader and match with that summary.

- **Image size caused most of the errors.** Five of the photos were only available as 150-pixel thumbnails, and they produced every serious error in the first round, such as linking a photo to the wrong event.
- **Two changes fixed the guessing.** The app now detects thumbnails and tells Claude, and a stricter prompt says to name people, places or events only when the catalog title or visible text supports them. Accuracy went from 4.45 to 4.90, and from 3.4 to 4.6 on the thumbnails.
- **Completeness didn't improve** (4.40 → 4.35). A careful prompt stops made-up details, but it can't make a 150-pixel image show what isn't visible.
- **Four other models graded the descriptions blind.** Claude's ranked first with every judge, but its lead was clear over only two of the four models.

## What I'd change

- **Test v2 on new photos.** Its rules came from the first round's mistakes on these same 20 photos, so a fair test needs a fresh set.
- **Cut the filler.** Several v2 descriptions now open with "no text is visible on the image", which a screen-reader user has to sit through.
- **Test with blind users.** "Usefulness to a blind reader" is my own judgment, not something I've tested with screen-reader users.
