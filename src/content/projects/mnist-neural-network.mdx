## Overview

I wrote a handwritten digit classifier with only Python and NumPy: no machine learning framework and no automatic differentiation. I wanted to understand how a neural network actually learns, so I built every part myself with an AI coding assistant and derived backpropagation by hand.

`torchvision` is used for one thing only: downloading the raw MNIST files. The data becomes plain NumPy arrays straight away, and PyTorch isn't used anywhere else.

## How it works

- **Network.** A `[784, 128, 64, 10]` fully connected network with ReLU and He initialization. Each 28×28 image is flattened into 784 values.
- **Loss.** Softmax with cross-entropy, computed through log-softmax so it stays stable for extreme values.
- **Backpropagation.** Derived by hand with the chain rule for every layer. I checked it against centered finite differences: the two gradients agree to a relative error of about 1e-9.
- **Training.** Mini-batch SGD with the data shuffled every epoch, tracking loss and train and validation accuracy.
- **Choosing settings.** I swept learning rate, hidden layer width and batch size one at a time, each across 3 seeds. The spread across seeds shows how much a score moves by chance, so a smaller difference doesn't count as evidence. A learning rate of 1.0 looked fine with one seed (95.6%) but collapsed to 12% with another.
- **Final settings:** learning rate 0.1, batch size 16, 20 epochs. The test set was used exactly once, after every setting had been chosen on a separate validation set.

## Results

**98.32% accuracy on the 10,000-image MNIST test set** (168 mistakes). That is test-set accuracy on MNIST's own scanned digits. Digits you draw yourself, like in the demo above, are usually harder for the network, because they don't look quite like the images it trained on.

Validation accuracy was also 98.32%. Since no decision was made using the test set, that match suggests choosing settings on the validation set didn't overfit to it.

I chose 20 epochs to land in the flat, stable stretch instead of on one lucky epoch.

## What I'd change

- **Build a CNN version to compare against.** A convolutional network looks at nearby pixels together, which should help with the shape confusions above. I'm aiming for about 99%.
- **Look at the learning rate for batch size 16.** The spikes at epochs 12 and 15 look like bad steps from a learning rate that's a bit high for that batch size.
